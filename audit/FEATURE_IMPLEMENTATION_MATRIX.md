# Feature implementation matrix

Status applies to the primary path described. Runtime scope is the local deterministic configuration unless explicitly stated. Optional backends receive separate judgments below. Each score uses the requested 0–100 anchors.

| Component | Status / score | Implementation and integration evidence | Demonstrated behavior | Gaps and remaining work |
|---|---|---|---|---|
| User interface and input | IMPLEMENTED AND VERIFIED · 90% | `frontend/src/components/ConsensusWorkspace.jsx` (`ConsensusWorkspace`, `ReviewCard`), `frontend/src/consensusApi.js` (`request`) | Real HTTP question/context submission, model selection, responses and synthesis panels, review and rerun. Edge smoke exercised claims, graph, correction and memory. An alert handles HTTP failures. The file control reads text locally (TXT, MD, CSV, JSON), cuts it to 50,000 characters, and rejects files over 200 KB. | File picker, accessibility and failure-state usability need dedicated browser assertions. PDF, OCR and binary uploads are absent. |
| Multi-model orchestration | IMPLEMENTED AND VERIFIED · 75% | `app/orchestration/engine.py` (`ConsensusEngine.run`), `app/orchestration/schemas.py` (`ConsensusRequest`), `app/providers/http.py` (`generate`) | Same question/context is sent independently with asyncio.gather. Request model IDs, response metadata, latency, partial failures, single fallback and bounded extra consultation are recorded. CHEAP begins with two models, other modes up to three. Timeouts, bounded retry and 429 handling exist. Pipeline, retry and fallback fixtures passed. | Live independence, correlated model families, latency and provider outages need measurement. BALANCED and HIGH_ACCURACY have the same initial count and escalation rule. |
| Provider/API integration | IMPLEMENTED AND VERIFIED · 75% | `app/providers/registry.py` (`get_provider`), `app/providers/http.py` (`HTTPProvider`), `backend/openrouter.py` (`query_model`) | OpenRouter, Gemini, Groq, Anthropic and OpenAI parse provider-specific HTTP fixtures. | Evidence verification and RAG | PARTIALLY IMPLEMENTED · 50% | `app/retrieval/service.py` (`RetrievalService.ingest`, `retrieve`), `app/retrieval/vectors.py`, `app/evidence/engine.py` (`EvidenceEngine.assess`) | Text chunks and validated memory are retrieved for question and claim queries. | Intelligent aggregation | IMPLEMENTED AND VERIFIED · 75% | `app/aggregation/strategies.py` (`factors_for`, `EvidenceAware`, `KnowledgeAware`), `app/aggregation/reliability.py` (`ReliabilityProfiles`) | Four strategies, including a majority baseline. | Confidence and uncertainty | PARTIALLY IMPLEMENTED · 50% | `app/confidence/engine.py` (`ConfidenceEngine.answer`), `app/confidence/calibration.py` (`held_out_experiment`), `app/orchestration/engine.py` | Claim scores, caps, model coverage, answer uncertainty, review and retrieval escalation are active.
