# Development roadmap

The phases extend working code. Effort estimates assume one experienced engineer, an available domain reviewer, one supported text domain, existing provider accounts and isolated test services. Person-hours include implementation and checks. Reviewer recruitment, procurement, annotation scale and paid-provider availability can change elapsed time materially.

| Phase | Work and first files | Depends on | Test and exit criterion | Hours |
|---|---|---|---|---:|

**Total: 232–464 person-hours.** This scopes a defensible single-domain research prototype. Production operations at organization scale require separate sizing.

## Next five changes in order

1. **Make the demo and configuration reproducible.** Start in scripts/start.ps1, app/orchestration/schemas.py, app/orchestration/engine.py and app/providers/http.py. Check unset, blank, malformed and valid price maps plus explicit live/mock selection. Run tests/unit/test_providers.py, tests/integration/test_provider_fallback.py and scripts/browser_smoke.cjs against disposable state.
2. **Close the service verification gap.** Work in compose.yaml, migrations/env.py, tests/integration/test_postgres.py and tests/unit/test_qdrant.py; add actual-service integration cases alongside the mocks. Exercise migrations, restart, version conflict and current-vector filtering.
3. **Freeze evaluation labels and eliminate circular measurements.** Extend app/evaluation/dataset.py, runner.py and tests/evaluation/test_framework.py. Prove splits are disjoint, repeats call the provider independently, contradiction labels are explicit, and held-out gold cannot seed memory.
4. **Fix measured semantic misses.** Extend app/claims/extractor.py, app/comparison/relations.py and semantic.py against labeled cases. Run tests/unit/test_claims.py, test_relations.py and test_evidence.py and compare per-class performance on the frozen split.
5. **Make evidence scoped and incremental.** Start in app/evidence/schemas.py, app/retrieval/service.py and app/knowledge/store.py. Measure recall at k, validate source version and scope, and rerun tests/integration/test_memory.py and the browser correction flow.

Defer additional providers, new UI modes, model fine-tuning and production confidence percentages until these gates hold. Reuse the upstream independent answer collection, anonymous rankings, chairman baseline, streaming chat and conversation viewer. The Mahthildis research contribution to evaluate is the interaction between claim-level relations, source-backed aggregation, uncertainty-triggered review and versioned memory reuse.
